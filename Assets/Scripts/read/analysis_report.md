# 프로젝트 분석 보고서

## 1. 자동소환/자동합성과 티어 시스템 연동 분석

### 1.1 자동소환 동작
- **위치**: `GirlFieldManager.Update()` → `TryAutoSpawn()`
- **동작 방식**:
  - 티어와 무관하게 항상 레벨 1을 소환
  - `autoSpawnTimer`가 `GetAutoSpawnInterval()` 간격으로 증가
  - `curSpawnCharge > 0`이고 필드가 가득 차지 않았을 때 소환
- **티어 연동**:
  - 소환된 캐릭터는 `ApplyVisibilityFor()`를 통해 현재 티어에 맞게 가시성 처리
  - 현재 티어가 아닌 레벨의 캐릭터는 자동으로 숨겨짐
- **결론**: ✅ **정상 작동** - 티어와 무관하게 자동소환이 작동하며, 가시성은 자동으로 처리됨

### 1.2 자동합성 동작
- **위치**: `GirlFieldManager.Update()` → `mergeManager.TryAutoMerge()`
- **동작 방식**:
  - `autoMergeTimer`가 `GetAutoMergeInterval()` 간격으로 증가
  - `fieldManager.girlList`를 순회하여 같은 레벨의 가장 가까운 두 캐릭터를 찾아 합성
  - 현재 발견 최대 레벨 이상은 자동 합성 금지
- **티어 연동**:
  - `girlList`에는 모든 티어의 캐릭터가 포함됨 (숨겨진 캐릭터도 포함)
  - `HideGirl()`은 `SetActive(false)`만 하므로, `girlList`에는 여전히 포함됨
  - `TryAutoMerge()`는 `RectTransform`을 사용하여 거리 계산을 하는데, 숨겨진 캐릭터의 위치도 유효함
- **잠재적 문제**:
  - ⚠️ **다른 티어의 숨겨진 캐릭터도 합성 대상이 될 수 있음**
  - 하지만 합성 후 생성된 다음 레벨 캐릭터는 `ApplyVisibilityFor()`를 통해 현재 티어에 맞게 가시성 처리됨
- **결론**: ⚠️ **기능적으로는 작동하지만, 의도하지 않은 티어 간 합성이 발생할 수 있음**

### 1.3 권장 개선사항
1. **자동합성 필터링 강화**:
   - `TryAutoMerge()`에서 현재 티어의 캐릭터만 합성하도록 필터링 추가
   - 또는 `girlList`를 현재 티어의 캐릭터만 포함하도록 분리

### 2.4 예상 플레이타임 (이론적 계산)

**가정**:
- 모든 레벨을 합성으로만 달성 (소환은 레벨 1만)
- 자동소환/자동합성 활성화
- 업그레이드 없이 기본 속도로 진행

**계산 방식**:
1. 레벨 1 소환: 200G 필요 → 200초 (기본 수익 1 G/s)
2. 레벨 2 합성: 레벨 1 두 개 필요 → 추가 소환 1회 필요 → 200G → 200초
3. 레벨 3 합성: 레벨 2 두 개 필요 → 레벨 1 네 개 필요 → 추가 소환 2회 필요 → 400G → 200초 (레벨 2 수익 2 G/s 기준)
4. ...

**실제 플레이타임**:
- 게임 밸런싱 목표: **레벨 25 도달까지 약 3시간**
- 현재 설정: `SUMMON_BASE_SECONDS = 200.0` (기존 60.0에서 약 3.33배 증가)
- 자동소환/자동합성 활성화 시 더 빠른 진행 가능
- 업그레이드(수동 소환 속도, 자동 소환/합성 속도 등)로 추가 가속 가능

### 2.5 밸런싱 검증
- ✅ 소환 가격이 3배 증가하여 플레이타임이 약 3시간으로 조정됨
- ✅ 반올림으로 가격이 깔끔하게 표시됨
- ⚠️ 실제 플레이테스트 필요: 자동소환/자동합성 활성화 시 예상보다 빠를 수 있음
