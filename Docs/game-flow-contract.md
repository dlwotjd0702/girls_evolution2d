# 기존 게임 흐름과 보존 기준

2026-08-28 소스·씬·Addressables 원본 대조 후 기록. 플레이 측정 결과와는 구분한다.

## 실제 연결

1. Build Settings의 Intro → Ingame. SimpleSceneLoader.Load가 버튼의 씬 이름을 받는다.
2. GameSystem이 GirlDataManager로 girl.csv를 읽고 SD/LD 라벨을 로드한다. SaveManager는 로컬 우선 복원, 필요하면 클라우드 선택을 진행한다. 필드는 AssetsReady를 기다린 뒤 저장된 레벨 목록을 복원한다.
3. 무료 소환과 자동 소환은 같은 충전을 소비해 Lv.1을 만든다. 구매 소환은 현재 필드 최고 레벨 - 2까지만 표시한다. 구매 횟수에 따른 가격 증가도 유지한다.
4. 동일 레벨 두 캐릭터를 합성해 다음 레벨을 얻는다. +2 도약은 기존 확률/최고 단계 제한을 따른다. CSV mergeCount=3인 행도 실제 런타임은 두 명을 사용한다. 이번 작업에서 합성 규칙을 바꾸지 않는다.
5. 평소 필드는 SD, 첫 발견 연출과 도감 상세는 LD를 사용한다. 캐릭터는 단일 UI Image이며 이동·점프는 Transform tween이다. 스프라이트 시트/본 애니메이션이 아니다.
6. 9 / 17 / 25에 월드가 해금된다. 전체 캐릭터를 하나의 목록/풀로 유지하고 현재 월드에 맞게 표시한다. 숨겨진 월드의 캐릭터도 수익 계산과 저장에 포함된다.
7. 24+24 → 25. 이후 25 도달은 새 레벨 ID를 만들지 않고 level25UpgradeLevel에 누적한다. 실제 최고 레벨은 계속 25다.
8. 최종 캐릭터가 있을 때 환생 가능. 도감/보석/환생 강화/계승은 유지, 필드/골드/회차 강화/월드 해금은 초기화한다. 시작 자금은 기존 계산을 유지한다.
9. 저장은 ISaveable 수집 방식이다. 캐릭터는 레벨만 저장하며 위치는 재배치한다. ID/레벨/라벨/저장 필드명 변경은 기존 복원에 영향을 준다.

## 이번 보완의 경계

- 25레벨, 4월드, 해금 임계값, 합성 재료 수, 소환 해금, 기존 가격/확률/수익 공식을 유지한다.
- 첫 수정의 보상 계산 순서·보석 이중 결제·중복 지급/합성 취소 처리는 유지한다. 보석 강화 보존은 기존 주석에 명시된 의도를 구현한 것이다.
- 환생 후 충전 가득과 Lv.1 두 명 지급은 편의 변경이다. 기존 첫 게임 시작과 튜토리얼에는 적용하지 않는다.
- 아트 교체는 동일 레벨/SD 또는 LD 역할 안에서만 한다. 추가 캐릭터 시안은 합성 체인에 자동 삽입하지 않는다.
- 기존 금테/꽃무늬/두루마리 패널 이미지를 유지한다. 단색으로 교체했던 환생/상단은 원래 이미지를 복원한다. 모서리 처리로 버튼 이벤트, 자식 계층, 활성화 조건을 바꾸지 않는다.
- 기존 플레이어 save.json은 수정하지 않는다. 구버전 강화의 구매 통화는 복원 불가능하므로 첫 수정의 보수적 마이그레이션 정책은 별도 변경 기록을 참고한다.

## 확인된 후속 위험

- 로딩 실패에도 AssetsReady=true가 될 수 있고, 광고 대기/클라우드 복구와 입력 가능 시점이 분리되어 있다. 이번 아트 작업에서 부팅 경로 전체를 재작성하지 않는다.
- CSV의 수익 값은 합성 일회 보너스에도 사용되지만 실제 초당 수익은 EconomyManager 공식이다. 둘을 단순 통합하면 경제 밸런스가 달라진다.
- 캐릭터 14 등 일부는 SD와 LD의 색/복장이 다르다. 포즈만 리터칭할 때도 캐릭터의 기존 식별 요소를 유지한다.
- 실제 Android/광고/결제/클라우드 통합 흐름은 별도 기기 검증이 필요하다.
