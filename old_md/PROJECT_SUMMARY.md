# 프로젝트 기술 요약서

## 현재 기준 업데이트 메모 (요약)

- **수익 계산**: `GirlFieldManager.ComputeIdleGoldPerSec()`에서 `EconomyManager.GetLevelIncomePerSec()` 합산
  - 25단계는 1개 캐릭터 수익에 `level25UpgradeLevel` 스택을 곱해 반영
  - 계승 등급 배수 × 환생 상점 배수 적용
- **저장 방식**: 로컬 JSON 파일 + PlayerPrefs 호환 저장 (백업 포함)
- **환생 상점 파사드**: `PrestigeShopManager`가 `PrestigeManager`의 UI/표기 연동 파사드 역할
- **소환 비용 기준**: 레벨별 소환 비용은 200초 수익 기반 곡선
- **환생 포인트**: 레벨 25 스택 + 하위 레벨 + 강화 레벨 기반으로 계산

## 도입 기술 및 수행 직무

### 1. 클라우드 저장 시스템 구축
Google Play Games SDK 기반 클라우드 저장 시스템을 설계 및 구현했습니다. 로컬 저장과 병행하여 데이터 안정성을 확보하고, 오프라인 환경에서도 캐시를 활용한 저장/로드가 가능하도록 구현했습니다. 충돌 해결 전략(최신 시간 기반, 수동 선택)을 적용하여 사용자 데이터 손실을 방지했습니다.

### 2. 인앱 구매 및 프리미엄 통화 시스템
Unity Purchasing v5를 활용한 인앱 구매 시스템을 구현했습니다. 보석(Gem) 통화 관리, 광고 제거 상품(Non-consumable), 가격 캐싱 및 로컬라이제이션을 처리했습니다. 구매 실패 시 자동 재시도 및 사용자 피드백 시스템을 포함했습니다.

### 3. 광고 통합 및 보상 시스템
Google Mobile Ads SDK를 통합하여 리워드 광고 시스템을 구현했습니다. 광고 준비 상태 모니터링, 자동 로딩, 광고 제거 구매 시 자동 보상 지급 로직을 개발했습니다. 인터페이스 기반 설계로 광고 SDK 교체가 용이하도록 구조화했습니다.

### 4. 환생 시스템 및 게임 밸런싱
환생 포인트 계산 알고리즘을 설계하고, 12종 환생 업그레이드 상점을 구현했습니다. 지수적 비용 곡선(base, growth factor)을 적용하여 장기적인 게임 진행을 고려한 밸런싱을 수행했습니다. Python 스크립트를 활용하여 만렙 비용을 계산하고 리밸런싱을 진행했습니다.

### 5. 자동 합성 알고리즘 최적화
O(N²) 완전 탐색 대신 조기 종료 전략을 적용하여 성능을 최적화했습니다. 거리 계산 시 sqrMagnitude를 사용하여 제곱근 연산을 제거하고, HashSet을 활용한 중복 합성 방지 로직을 구현했습니다. +2단 도약 확률 시스템(최대 50% 캡)을 통합했습니다.

### 6. 성취도 시스템 연동
Google Play Games SDK의 성취도 API를 활용하여 5가지 성취도를 자동 체크 및 달성 처리하는 시스템을 구현했습니다. 주기적 폴링(5초 간격)을 통해 레벨, 클릭 수, 플레이 시간, 강화 레벨, 티어 달성을 추적합니다.

### 7. 에셋 관리 및 비동기 로딩
Unity Addressables를 활용하여 스프라이트 에셋을 비동기 로딩하도록 구현했습니다. CSV/TSV 데이터 파싱을 통해 캐릭터 정보를 관리하고, StreamingAssets를 활용한 런타임 데이터 로딩을 구현했습니다.

### 8. 이벤트 기반 아키텍처
C# 이벤트를 활용하여 매니저 간 느슨한 결합을 구현했습니다. UI 갱신은 값 변경 시에만 트리거되도록 가드 로직을 추가하여 불필요한 업데이트를 방지했습니다. 싱글톤 패턴과 DontDestroyOnLoad를 활용한 매니저 생명주기 관리.

### 9. 다국어 지원 시스템
LocalizationManager를 구현하여 한국어/영어 다국어를 지원합니다. TextMeshPro를 활용한 고품질 텍스트 렌더링 및 동적 폰트 교체 기능을 포함했습니다.

### 10. 오프라인 보상 시스템
마지막 저장 시간과 현재 시간을 비교하여 오프라인 기간 동안의 골드를 계산하는 시스템을 구현했습니다. 최대 보상 시간 제한 및 보상 배수 적용 로직을 포함했습니다.

# 프로젝트 전체 분석 보고서

본 보고서는 현재 코드베이스를 기준으로 핵심 시스템, 데이터 흐름, 성능 최적화 포인트를 정리한 문서입니다. 특히 **합성 시 적용되는 거리 계산 메커니즘**을 상세히 기술했습니다.

## 1. 범위 및 문서 구조
- **루트 문서**: `README.md`, `SETUP.md`
- **코드 문서**: `Assets/Scripts/README.md`
- **기존 요약 문서**: `old_md/PROJECT_SUMMARY.md` (본 문서)

## 2. 시스템 아키텍처 개요
- **초기화 플로우**: `SaveManager -> GameSystem -> 데이터/스프라이트 로드 -> Ready 이벤트`
- **게임 루프**: `GirlFieldManager.Update()`에서 자동 소환/자동 합성/골드 수익을 주기적으로 처리
- **저장 시스템**: 주기 저장 + 백업 파일 생성, ISaveable 기반 확장 구조

## 3. 핵심 시스템 분석
### 3.1 캐릭터/필드
- `GirlFieldManager`가 필드의 캐릭터 리스트를 관리하고, 소환/합성/발견 연출을 담당합니다.
- 캐릭터는 `GirlCharacter`가 입력(드래그/클릭)과 애니메이션을 담당합니다.

### 3.2 합성 시스템
- `GirlMergeManager`가 드래그 합성 및 자동 합성을 담당합니다.
- 합성 시 **+2단 도약 확률**을 계승 등급 + 프레스티지 상점에서 합산(최대 50%)하여 적용합니다.### 3.3 경제/업그레이드
- `EconomyManager`가 골드 수익/업그레이드 비용/클릭 보너스를 통합 관리합니다.
- 수익은 레벨 기반 지수 성장(`2^(레벨-1)`)을 기본으로 하며, 각종 배수/보너스를 추가 적용합니다.

### 3.4 저장/클라우드
- `SaveManager`가 로컬 저장/백업을 수행하고, `CloudSaveManager`가 Google Play Games 기반 클라우드 저장을 담당합니다.
- 충돌 해결은 최신 시간 기반 + 수동 선택 정책을 사용합니다.

## 4. 데이터/에셋 파이프라인
- **캐릭터 데이터**: CSV/TSV 로딩 (`GirlDataManager`)
- **스프라이트**: Addressables 기반 SD/LD 비동기 로딩
- **StreamingAssets**: 런타임 데이터 로딩 지원

## 5. 합성 거리 계산 메커니즘 상세

### 5.1 드래그 합성 대상 하이라이트
사용자가 캐릭터를 드래그할 때, **같은 레벨**의 가장 가까운 대상만 하이라이트합니다.

- **좌표계**: `RectTransform.localPosition` (UI 로컬 좌표)
- **거리 계산 방식**: `Vector3.sqrMagnitude`를 사용하여 제곱 거리 비교
- **탐색 반경 제한**: 180 픽셀 이내만 탐색

핵심 로직 요약:
- 드래그한 캐릭터의 위치/레벨을 캐싱
- 같은 레벨만 대상으로 순회
- `distSqr`가 현재 `bestDistSqr`보다 작을 때만 후보 갱신
- 가장 가까운 1개만 하이라이트

### 5.2 자동 합성 거리 계산
자동 합성은 **필드 내 같은 레벨 페어** 중 가장 가까운 쌍을 선택합니다.

- **좌표계**: `RectTransform.localPosition`
- **거리 계산 방식**: `Vector3.sqrMagnitude` 제곱 거리 비교
- **최대 레벨 보호**: 현재 필드의 발견 최대 레벨은 자동 합성 대상에서 제외
- **중복 합성 방지**: `_mergingSet`으로 합성 중인 개체 재선택 방지
- **성능 보호**: `n > 80`이면 첫 유효 페어에서 조기 종료

핵심 로직 요약:
- 전체 리스트에서 같은 레벨 페어를 이중 루프로 탐색
- `bestDistSqr`가 가장 작은 페어를 선택
- 개체 수가 많을 경우 O(N²) 스파이크를 줄이기 위해 조기 종료

### 5.3 성능 고려 사항
- 제곱 거리 비교로 `sqrt` 연산 제거
- 드래그 하이라이트는 반경 제한으로 후보군을 축소
- 자동 합성은 **최대 레벨 보호 + 조기 종료**로 UI/게임 스파이크 방지
